🐳 Docker Desktop 重启图文指南

针对「构建时守护进程崩溃 (use of closed network connection)」的 4 种重启法 + 验证 + 后续部署

适用：Windows 10/11 + Docker Desktop 4.x

! 为什么会需要重启？

本次阶段四部署卡在 Docker Desktop 的 WSL 引擎管道中途崩溃，与代码无关

⚠️ 报错特征：http2: server: error reading preface from client //./pipe/dockerDesktopLinuxEngine: file has already been closed —— 这是 Docker Desktop 守护进程不稳定，不是你的 Dockerfile / compose 有问题（它们已通过 docker compose config 校验，前端 build 也已 CACHED 验证）。 重启守护进程即可恢复。
✅ 推荐顺序：先试 方法二（wsl --shutdown 彻底重启），它对 WSL 引擎崩溃最有效；若不方便用命令行再用方法一。

1 方法一：系统托盘右键重启（最快）

适合：临时卡顿、图标转圈、右键菜单还能点出来

右下角任务栏找到鲸鱼图标 → 右键 → 选「Restart / 重启」
1
看右下角系统托盘 （任务栏右侧的 ^ 小箭头展开后，找到 🐳 鲸鱼图标）。若图标在转圈，说明守护进程卡住。
2
右键鲸鱼图标 → 在弹出菜单中点击「Restart（重启）」。Docker 会先退出再自动拉起。
3
等待鲸鱼变静止 图标从旋转变为静止，托盘提示 “Docker Desktop is running” 即成功。
💡 若右键菜单里只有「Quit / 退出」，点退出后用 开始菜单 → Docker Desktop 重新打开也可达到同样效果。

2 方法二：wsl --shutdown 彻底重启（★推荐）

适合：本次 WSL 引擎管道崩溃 —— 它强制关闭底层 WSL 虚拟机，最干净

图：管理员 PowerShell 执行 wsl --shutdown，再从开始菜单打开 Docker Desktop
# 1) 以管理员身份打开 PowerShell（Win+X → 终端(管理员) 或 Windows PowerShell(管理员)） wsl --shutdown # 强制关闭 WSL2 虚拟机，清掉崩溃的 docker 引擎 # 2) 等 5~10 秒，确认无残留： wsl -l -v # 应显示 STOPPED 或无 docker-desktop 条目 # 3) 从「开始菜单 → Docker Desktop」重新打开，等鲸鱼图标变静止
✅ 这是解决 “use of closed network connection” 的最有效手段，因为它把整个 WSL 网络栈都重建了。

3 方法三：任务管理器强杀进程

适合：Docker Desktop 界面无响应、右键菜单都点不出来

图：任务管理器里结束 Docker Desktop / Backend 进程
1
Ctrl+Shift+Esc 打开任务管理器 → 切到「详细信息」选项卡。
2
结束进程 找到 Docker Desktop.exe 与 Docker Desktop Backend.exe，逐个右键 → 「结束任务」。
3
重新打开 开始菜单 → Docker Desktop，等鲸鱼静止。

4 方法四：Windows 服务重启

适合：Docker 以 Windows 服务方式安装、且前面方法都不奏效

# 管理员 PowerShell Restart-Service "com.docker.service" # 重启 Docker 服务 # 或等价命令： net stop com.docker.service # 停止 net start com.docker.service # 启动
💡 服务名一般为 com.docker.service。若提示“服务不存在”，说明你用的是 WSL 后端而非 Hyper-V/服务后端，请用方法二。

✓ 重启后验证是否真的恢复

两条命令，看到 ServerVersion 输出版本号即代表守护进程已活

docker info # 正常会打印 Server Version、Containers、Images 等信息 docker version # 同时显示 Client 与 Server 版本，Server 不再报错即为成功
现象判断
docker info 打印版本号，无报错✅ 守护进程已恢复，可继续部署
仍报 “cannot connect to the Docker daemon”❌ 没起来，重做方法二 / 重启电脑
鲸鱼图标静止 + 托盘提示 running✅ GUI 层面已就绪

▶ 守护进程恢复后：一键部署

在 feiyue-credit 项目根目录执行

cd feiyue-credit cp .env.example .env # 填入 WX_APP_SECRET / JWT_SECRET docker compose up -d --build # 构建并后台启动 frontend + backend # 浏览器打开 http://localhost:8080
✅ 届时前端（nginx:80→宿主机8080）会反代到 backend:8080，SQLite 数据落在 backend-data 卷，重启容器不丢数据。

症状处理
重启后立刻又崩溃升级 Docker Desktop 到最新版（Settings → Check for Updates）；旧版 WSL 引擎有已知 bug
wsl --shutdown 报错“没有权限”必须用管理员 PowerShell 运行；普通终端会失败
Docker 一直 “Starting…” 卡住Settings → Resources → WSL Integration 关掉再开；或重置为出厂（Settings → Reset）
公司电脑装了安全软件拦截把 Docker Desktop 加入白名单；必要时联系 IT 放行 WSL/虚拟化
BIOS 未开虚拟化进 BIOS 开启 Intel VT-x / AMD-V，否则 Docker 无法运行
⚠️ 若反复崩溃且影响工作，最稳的是：方法二彻底重启 → 仍不行就重启整台电脑，绝大多数 Docker 守护进程故障都能这样解决。
