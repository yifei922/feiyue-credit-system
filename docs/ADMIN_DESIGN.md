# 管理端优化方案（教师 / 管理员 / 课代表）

## 问题
原系统教师、管理员、课代表登录后**没有对应的管理程序**，无法在小程序里管理资料、用户、学分。

## 两个候选方案对比

| 维度 | 方案 A：小程序按钮 → webview 跳转网页后台 | 方案 B：直接在小程序内嵌管理功能（✅ 已采用） |
|------|------------------------------------------|----------------------------------------------|
| 实现成本 | 需另做一个 Web 管理站并托管（Vercel/自有服务器） | 复用现有后端 API，新增几个小程序页面即可 |
| 个人主体限制 | ⚠ webview 必须配置**业务域名**白名单，需 ICP 备案域名 | ✅ 不受业务域名限制，仅用自有 API 域名 |
| 老师使用路径 | 先开网页、再登录、跨端切换 | 在小程序内点「管理后台」直接进入，零切换 |
| 维护成本 | 两套前端（小程序 + Web） | 一套（小程序） |
| 适用管理规模 | 大（复杂表单、批量导入） | 中（班级场景足够：资料/用户/概览） |

## 决策：采用方案 B（小程序内嵌）

理由：
1. 本项目是**班级级**系统，管理动作少而轻（增删资料、重置学生密码、看概览），不需要复杂 Web 后台；
2. 你是**个人主体小程序**，webview 业务域名需备案域名 + HTTPS 托管，门槛高、运维重；
3. 后端 `/api/mp/admin/*` 与 `/api/users/*` 接口早已齐全，直接对接成本最低。

## 已落地页面（位于 `miniprogram/pages/admin/`）
- `index`：管理后台首页（角色徽章 + 概览数据 + 功能菜单）
- `resources`：资料管理（新增/编辑/删除，教师和管理员可用）
- `users`：用户管理（按角色筛选、一键重置密码，教师和管理员可用）

权限由后端 `isAdmin` / `requireRole` 中间件强制校验，前端只做入口显隐。

## 后续可选增强
若日后管理动作变复杂（如批量导入 Excel、审批流、数据看板），再补一个轻量 Web 后台并接入 webview 也不迟——后端接口可复用。
